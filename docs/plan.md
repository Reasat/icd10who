# ICD10WHO — Pipeline Plan

This document describes the full ETL pipeline for the `icd10who` Mondo ingest source repository.
The pipeline converts the WHO ICD-10 API into a validated LinkML YAML and a derived OWL component,
matching the behavior of `mondo-ingest` `components/icd10who.owl`.

---

## Source overview

| Aspect | Detail |
|--------|--------|
| Source name | ICD-10 WHO (World Health Organization) |
| Upstream | WHO ICD API — `https://icd.who.int/icdapi` |
| Acquisition format | Turtle (`.ttl`) generated by `icd10who_ingest` from the WHO OAuth2 JSON API |
| Auth | `CLIENT_ID` + `CLIENT_SECRET` (WHO ICD API credentials) — stored in `env/.env` |
| Version | No explicit version field from the API; the ingest targets the `latest` release unless overridden |
| IRI namespace | `https://icd.who.int/browse10/2019/en#/` — each code is `ICD10WHO[code]` |
| Hierarchy | `rdfs:subClassOf` present in the TTL output of `icd10who_ingest` |
| Synonyms | None in the source; exact synonyms generated from labels via SPARQL update |
| Definitions | None in the source |
| Obsolete terms | Not present in this source |
| Cross-references | None |

---

## Phase 1 — Acquire (`make ttl`)

**Script:** `icd10who_ingest/__main__.py`

1. Reads `CLIENT_ID` / `CLIENT_SECRET` from `env/.env`.
2. Obtains an OAuth2 bearer token from
   `https://icdaccessmanagement.who.int/connect/token` (`client_credentials`, scope `icdapi_access`).
3. Resolves the latest ICD-10 release URL via `GET https://id.who.int/icd/release/10`.
4. Walks the ICD-10 hierarchy via the API's `child` links, caching each node's JSON under `cache/`.
5. Serialises the result as Turtle to `icd10who.ttl` at the repo root using `rdflib`.

**Output:** `icd10who.ttl`

> **Note:** The repo also maintains a committed `icd10who.ttl` from the upstream
> [monarch-initiative/icd10who](https://github.com/monarch-initiative/icd10who) release.
> The default `ICD10WHO_TTL` in the Makefile points at the GitHub latest-release URL so the
> ROBOT build works without running the WHO API ingest.

## Phase 2 — Mirror (`make tmp/mirror-icd10who.owl`)

**Tool:** ROBOT

```
robot merge -I $(ICD10WHO_TTL) \
    odk:normalize --add-source true \
    -o tmp/mirror-icd10who.owl
```

Mirrors the upstream TTL exactly as `mondo-ingest` does. The `odk:normalize` step adds
`oboInOwl:source` provenance triples and standardises serialisation.

**Output:** `tmp/mirror-icd10who.owl`

---

## Phase 3 — Relevant signature (`make tmp/icd10who_relevant_signature.txt`)

**Tool:** ROBOT query

```
robot query -i tmp/mirror-icd10who.owl \
    -q sparql/icd10who-relevant-signature.sparql \
    tmp/icd10who_relevant_signature.txt
```

The SPARQL query selects every distinct IRI appearing in the graph whose string starts with
`https://icd.who.int/browse10/2019/en#/`. This is the complete WHO browse-10 namespace.

**Output:** `tmp/icd10who_relevant_signature.txt`

---

## Phase 4 — Component OWL (`make icd10who.owl`)

**Tool:** ROBOT (chained)

Steps (matching `mondo-ingest` `components/icd10who.owl` target):

1. `remove --select imports` — drop import declarations.
2. `rename --mappings config/property-map.sssom.tsv` — remap source property IRIs to Mondo IRIs
   (`--allow-missing-entities true --allow-duplicates true`).
3. Subset to signature:
   - `remove -T sig.txt --select complement --select "classes individuals" --trim false`
   - `remove -T sig.txt --select individuals`
4. SPARQL updates:
   - `sparql/fix_omimps.ru` — fix OMIM property punning (shared with ICD10CM).
   - `sparql/fix-labels-with-brackets.ru` — clean bracketed labels.
   - `sparql/exact_syn_from_label.ru` — generate `oboInOwl:hasExactSynonym` from `rdfs:label`.
5. `remove -T config/properties.txt --select complement --select properties --trim true` —
   strip properties not in the Mondo allowlist.
6. `annotate` — set ontology IRI and dated version IRI.

**Output:** `icd10who.owl`

> This OWL file is the canonical Mondo ingest artefact. It matches `components/icd10who.owl`
> in `mondo-ingest` when built from the same upstream TTL.

---

## Phase 5 — LinkML YAML (`make build-release` → `scripts/transform.py`)

**Script:** `scripts/transform.py`

Reads the ROBOT-preprocessed `icd10who.owl` using `rdflib` and serialises every
`owl:Class` in the WHO IRI namespace to `icd10who.yaml`, conforming to
`linkml/mondo_source_schema.yaml`.

Field mapping:

| OWL predicate | YAML slot |
|---------------|-----------|
| `rdfs:label` | `label` |
| `oboInOwl:hasExactSynonym` | `exact_synonyms` |
| `rdfs:subClassOf` (ICD10WHO IRI targets) | `parents` |
| `owl:deprecated` | `deprecated` |
| `obo:IAO_0000115` | `definition` |
| No WHO IRI parents / `owl:Thing` parent | `is_root: true` |

**Output:** `icd10who.yaml`

---

## Phase 6 — Validate

```
uv run python -m linkml.validator.cli \
    --schema linkml/mondo_source_schema.yaml \
    --target-class OntologyDocument \
    icd10who.yaml
```

Validates `icd10who.yaml` against the LinkML schema. Must exit 0 before releasing.

---

## Phase 7 — Derive LinkML OWL

```
uv run python -m linkml_owl.dumpers.owl_dumper \
    --schema linkml/mondo_source_schema.yaml \
    -o icd10who_from_linkml.owl \
    icd10who.yaml
```

Derives `icd10who_from_linkml.owl` from the validated YAML.
This OWL is a secondary artefact for OWL-native consumers.
The primary contract for Mondo ingest is `icd10who.yaml`.

> **Known limitation:** `linkml-owl` emits OWL Functional format; ROBOT may not load it
> cleanly in all cases (same limitation as `icd10cm`).

---

## Phase 8 — Release

GitHub Actions (`.github/workflows/release.yml`):

- Trigger: push to `main` touching pipeline files; weekly cron (Monday 00:00 UTC); manual `workflow_dispatch`.
- Environment: `obolibrary/odkfull:v1.6` Docker (ROBOT + ODK normalize plugin).
- Steps: checkout → `make build-release` → tag `vYYYYMMDD-<run_number>` → upload release assets.
- Release assets: `icd10who.yaml`, `icd10who.owl`, `icd10who_from_linkml.owl`.

---

## Phase 9 — Verification checklist

Before trusting a pinned release, run a diff against `mondo-ingest`:

- [ ] Term count in `icd10who.yaml` matches the source (typically ~12,000 ICD-10 WHO terms)
- [ ] `label` is non-null for all terms
- [ ] All `parents` references resolve to known term IDs
- [ ] `linkml-validate` exits 0
- [ ] `icd10who.owl` and `icd10who_from_linkml.owl` can be loaded by ROBOT or Protégé
- [ ] `robot diff --left icd10who.owl --right reference-icd10who-mondo-ingest.owl -o diff.md` shows no unexpected structural differences

> For diff validation, pin the upstream TTL to a fixed release tag and build the reference
> from `mondo-ingest` with the same pin. See `docs/discovery.md § Validation workflow` for
> the full procedure.

## Key design decisions

1. **No standalone `acquire.py`** — acquisition is handled by the `icd10who_ingest` package
   (`make ttl`) for local runs; the default `ICD10WHO_TTL` variable points to the GitHub
   latest-release URL so the ROBOT build works without WHO API credentials.

2. **Makefile, not justfile** — this is an OWL-based source; ROBOT orchestration fits naturally
   in a Makefile. `make build-release` is the single entry point used in CI.

3. **No generated Pydantic datamodel** — `scripts/transform.py` reads the component OWL with
   `rdflib` directly (no generated datamodel class needed) because the extraction input is
   already a processed OWL file, not a raw source format.

4. **Synonym generation via SPARQL** — `exact_syn_from_label.ru` generates `hasExactSynonym`
   from `rdfs:label` at the ROBOT stage (before extraction), consistent with the ICD10CM approach.

5. **Term IRI → CURIE** — WHO browse-10 IRIs (`https://icd.who.int/browse10/2019/en#/A00`)
   are mapped to `ICD10WHO:A00` CURIEs in the YAML using `iri_to_curie()` in `transform.py`.

## Local quick-start

```bash
# 1. Install deps
uv sync

# 2a. Build using GitHub latest TTL (no credentials needed)
make build-release

# 2b. Or: ingest from WHO API first (needs env/.env)
cp env/.env.example env/.env
# Edit env/.env with your CLIENT_ID and CLIENT_SECRET
make ttl
ICD10WHO_TTL=icd10who.ttl make build-release
```
